## Fixed Constraints

The implementation will preserve these values byte-for-byte:

- Title: `Peptide kaufen in Deutschland für Forschung & Analyse`
- Description: `Forschungspeptide für Labor und Analyse mit klaren Produktdaten, Packgrößen und COA-Status. Jetzt Produkte vergleichen!`

It will not modify backend code, Inbox/IMAP/SMTP behavior, consent, product
records, pricing logic, checkout logic, the order-enablement switch, dependencies,
or deployment files. It will not commit, push, merge, or deploy.

## Files and Interfaces to Inspect Before Editing

- `storefront/src/pages/index.astro`: current homepage catalog query, featured-product
  selection, price formatting, FAQ/JSON-LD source, headings, links, image behavior,
  and page-local responsive CSS.
- `storefront/src/layouts/BaseLayout.astro`: production announcement bar, brand/logo,
  search form, desktop navigation, mobile navigation behavior, global tokens, focus
  treatment, footer, consent mount, and lightweight cart-badge script.
- `storefront/src/components/Seo.astro`: canonical, robots, title/description,
  OpenGraph/Twitter, Organization graph merge, and structured-data serialization.
- `storefront/src/components/ProductCard.astro`: established product-image fallback,
  metadata guards, price conventions, and image loading/dimension patterns. The hero
  feature will not reuse the whole card if doing so prevents the mockup composition.
- `storefront/src/lib/catalog.ts`: `listProductsInSourceOrder`, `listCategories`,
  optional Medusa fields, build-catalog snapshot path, and availability helpers.
- `storefront/src/lib/pricing.ts`: existing centralized price utilities will be used if
  they match the featured card's minimum-price requirement; otherwise the existing
  homepage formatter remains page-local without changing pricing logic.
- `storefront/src/lib/links.ts`: `productPath`, `categoryPath`, and trailing-slash-safe
  internal paths.
- `storefront/src/lib/product-image-alt.ts`: structured German product image alt text.
- `storefront/src/lib/shop.ts`, `storefront/src/components/AddToCart.astro`, and
  `storefront/src/components/WebMCPTools.astro`: read-only confirmation that ordering
  remains gated and no ordering control is introduced by the homepage.
- `storefront/src/lib/metadata-output.test.ts`, `canonical.test.ts`,
  `canonical-output.test.ts`, `images.test.ts`, `faq-output.test.ts`,
  `operational-claims.test.ts`, and `links-output.test.ts`: existing regression
  contracts the redesign must continue to satisfy.
- The four category pages generated by `storefront/src/pages/kategorie/[handle].astro`
  and current Medusa category name/description records: content and routing source for
  the research cards.

## Expected File Changes

- Add `storefront/src/assets/homepage-scientific-hero.webp`.
  - This source-controlled asset path intentionally refines the spec's provisional
    `public/images/` path: importing from `src/assets` lets Astro generate optimized,
    hashed responsive output instead of copying one unprocessed public file. Approval
    of this plan approves that path correction.
- Change `storefront/src/pages/index.astro`.
  - Replace the homepage composition, keep catalog data server-rendered, preserve exact
    metadata/schema inputs, and add scoped responsive/token-based styling.
- Add `storefront/src/lib/homepage-output.test.ts`.
  - Add focused source and built-output regressions for structure, factuality, links,
    data binding, metadata, ordering state, images, and responsive navigation
    invariants.
- Change `storefront/src/layouts/BaseLayout.astro` only if the new composition needs a
  reusable color, translucent surface, or shadow token that cannot be expressed with
  existing tokens. No header, search, navigation, consent, footer, or cart script markup
  will be changed.
- Change existing tests only when an old assertion describes the former homepage
  structure rather than a still-valid invariant. Likely candidates are
  `storefront/src/lib/images.test.ts`, `faq-output.test.ts`, and
  `operational-claims.test.ts`; exact metadata and canonical expectations remain
  unchanged.

No other file is expected to change.

## Mockup Conflicts and Resolutions

- The mockup brand says `Buy Peptides`; the implementation keeps the production
  `PeptideEinkaufen` logo and shared header.
- The mockup uses a fixed BPC-157 `Top product`; the repository has no supported
  featured/ranking rule, so the existing first-peptide-in-source-order selection remains
  and no badge claims popularity.
- The mockup shows a 4.9/5 Google score and review count; no verified review source
  exists, so the area becomes linked factual trust navigation with no rating markup.
- The mockup includes named scientist portraits and quotations; no consented source
  exists, so the panel becomes `Qualität und Transparenz im Überblick` with factual
  repository links.
- The mockup asserts `≥ 98%`, `COA inklusive`, fast shipping, and secure payment;
  these are not universal verified facts. The featured card shows only fields on the
  selected real product, while supporting sections point visitors to the pages where
  status and policy information can be checked.
- The mockup uses `Jetzt bestellen` and other active commerce language; ordering is
  closed, so all homepage actions are informational (`Produkt ansehen`, `Produkte
  ansehen`, `Support kontaktieren`) and no cart/checkout control is added.
- The proposed H1 contains `kaufen`, while the CTA restriction forbids transactional
  wording during closure. The H1 is retained exactly because it is explicitly approved
  SEO copy; action labels remain non-transactional and the page does not imply an order
  can be completed.
- The mockup's photographic hero is not present in the repository. A purpose-generated,
  claim-free decorative asset will supply the atmosphere while all meaningful content
  remains accessible HTML and Astro handles optimized delivery.
